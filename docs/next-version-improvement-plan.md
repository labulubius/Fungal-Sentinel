## P0：下一步优先处理

### 1. 修复横竖屏切换后的相机预览方向

**状态：已完成，待真机复核。**

模拟器复查未重现画面横置，但确认旧实现直接用视图宽高作为相机缓冲区尺寸，导致竖屏预览比例明显拉伸。现已根据显示旋转、传感器方向和摄像头朝向选择受支持的预览尺寸，并为 `TextureView` 设置居中裁切变换；表面尺寸变化时会重新计算。

**要求：**

- 根据显示旋转、传感器方向和前后摄方向计算预览变换；
- 横屏和竖屏切换后保持画面方向正确；
- 保持合理的中心裁切比例，避免拉伸；
- 不破坏 Camera2 暂停/恢复和 RAW 拍摄生命周期。

**验收：** 竖屏 → 横屏 → 竖屏重复切换多次，预览方向、比例和拍摄均正常，无需重启 App。

模拟器已完成正反横竖屏及连续六次切换检查，画面方向和比例正常，未出现崩溃或相机会话错误；不同传感器方向仍需在真机复核。

### 2. 真机 Camera2/RAW/DNG 验证

**状态：已有 vivo V2303A 测试机，待完整执行四步流程。** 当前已完成安装、启动和窄屏界面检查，但尚未确认 DNG 可读性、400 ms 实际元数据及完整定量流程。

至少验证：

- DNG 文件可正常保存并被常见软件读取；
- 400 ms 曝光、ISO、无穷远焦距实际生效；
- 自动曝光模式和部分能力降级逻辑正确；
- 暂停/恢复、锁屏返回和连续拍摄不闪退；
- 样品、标准品和校准拍摄使用一致的参数和元数据。

### 实时预览流畅度说明

vivo V2303A 在移动手机时仍可感到预览不流畅。v1.2.2 已为自动曝光预览请求设备公布的稳定 `[30,30]` FPS 范围，但用户未感到明显改善。该问题不影响 RAW 数据和光谱计算，暂不继续修改 Camera2 核心流程。手动 400 ms 曝光的理论上限约为 2.5 FPS，卡顿属于物理限制；若以后继续调查，应先记录实际帧时间戳、曝光时间和 frame duration，不要继续猜测式调参。

## P2：特殊布局与开发支持

### 11. 限宽操作界面与可选的专用半屏模式

**状态：组会提出的限宽界面已实现；可切换的专用半屏模式不是现有功能。**

现有 `SidebarPanel.kt` 在展开详情时采用紧凑目录栏（`CompactLayout.compactSidebarWidth = 56.dp`），右侧详情面板设置最大宽度（`detailPanelMaxWidth = 360.dp`），使相机预览仍有可见空间；并支持窄屏及横屏滚动。这实现的是**限制控件占用空间、保留预览**的界面需求，不能描述成“半屏界面尚未实现”，也不能声称所有设备上严格占屏幕的 50%。

以下只是**若将来需要独立的、可开关的半屏模式**才需讨论的额外需求，并非当前限宽界面的验收前提：

- 是否需要手动切换及记忆模式；
- 是否要求所有关键操作严格位于指定的物理半屏；
- 如需基于传感器自动触发，应允许用户手动覆盖。

**待确认（仅针对额外专用模式）：** 可见区域、装置方向和触发条件。

## 实施与回滚规则

每次只处理一个小项目：

1. 修改前检查 Git 工作区，避免覆盖现有未提交内容；
2. 只修改当前项目所需文件；
3. 运行相关单元测试、编译检查和可执行的模拟器/真机验证；
4. 测试通过后创建独立 Git commit；
5. 在结果中记录提交哈希和验证方式；
6. 需要撤销时优先使用 `git revert <commit>`，保留完整历史。
